# 界面：技术指标与设计

第一章要交付的不是三角形，是一个**完整可用的登录/注册界面**：用户名、密码、
邮箱、上传头像，动效丝滑，界面因果完整。

验收标准是 `~/blog/source/_posts/我的UI设计观.md` 那五条——反馈、因果、连续、
信息密度、新奇度。这份文档的作用是把那五条翻译成技术选型和可测的数字，而不是
形容词。

---

## 0. 起点：现在有什么

模板现在还停在三角形阶段（平铺文件 + 顶点缓冲）：

```
template/src/  main app platform instance debug surface device swapchain
               color memory vertex_buffer shader pipeline frame draw error
template/shaders/  triangle.slang  color.slang
```

已经能用的：Vulkan 1.3 动态渲染 + synchronization2 的整套骨架、交换链重建、
每帧资源、**OKLCH 作者面 + Display P3 输出**（`color.h/.cpp`，已在真机验证
输出色域为 Display P3）。

第一章前九步会把它变成：**实例化圆角矩形管线** + `gpu/` `ui/` `app.*` 三层
架构（分层靠 `#include` 图在编译期守住）。界面工作从第九步之后开始，本文档
描述的都是那之后的事。

## 1. 渲染：一条管线画完几乎所有东西

核心是**带圆角半径的矩形有向距离场**，`fwidth` 做抗锯齿。它不是「一种图形」，
而是一族：

| 要画的东西 | 怎么表达 |
|---|---|
| 矩形 | `radius = 0` |
| 圆 | 正方形 + `radius = 半边长` |
| 胶囊 / 线段 | 线段按半笔宽膨胀 |
| **文字笔画** | 一段线 + 笔宽，**就是**圆角矩形 |
| 描边 | 同一个距离场取 `abs(d) - w` |
| 投影 / 辉光 | 同一个距离场取不同阈值 + 模糊 |

「线段膨胀 w/2」与「`radius = w/2` 的圆角矩形」是**恒等**的，不是近似——已数值
验证有向距离最大偏差 `8.9e-16`（双精度舍入量级）。

工程后果：整个界面——按钮、输入框、卡片、分隔线、光标、进度条、全部文字——
走同一条实例化管线，一次 `vkDrawIndexed(instanceCount = N)` 画完。`gpu/` 层
在第一章之后一行都不用改。

**唯一的例外是头像**，见 §9。

### 指标

- 每帧一次实例缓冲上传，一次 draw call；实例数量级 10³ 起步不成问题
- 每实例数据：位置、尺寸、半径、颜色、变换索引、裁剪索引
- 逐帧变化的少量参数走 push constant（Vulkan 保证至少 128 字节）
- 帧预算：60 Hz → 16.7 ms，120 Hz → 8.3 ms

## 2. 文字：笔画骨架，不引 HarfBuzz

用 `~/game/onedot44mb_game` 那套**笔画骨架矢量字库**：FZE1 位流，数据来自
GlyphWiki/KAGE，**439 KB 覆盖 GBK 20923 汉字 + ASCII + 标点**，许可无限制商用。

选它而不是 HarfBuzz + FreeType 的理由，按重要度：

1. **零新增管线。** 笔画就是线段，线段就是圆角矩形，直接复用 §1 那条管线。
   HarfBuzz 那条路要额外背上纹理图集管线 + 3–5 MB 字体文件 + 五平台交叉编译
   一个 C 库。
2. **可逐笔动画。** 笔画树能逐笔生长、崩碎、笔锋粗细随时间变——这是设计观
   第 2、3 条（因果、连续）对文字的直接要求。图集方案里字是一张贴图，做不了。
3. **无图集，任意缩放。** 不用为每个字号烘焙，不会糊。

### 已知短板

小字号（**14 px 以下**）没有 hinting 会飘。这是选型时就接受的代价。

触发换方案的信号，任意一条成立就该重新评估：需要 12 px 密排正文、需要
shaping 的书写系统（阿拉伯文、天城文）、需要支持用户自带字体。

字体活在 `ui/` 层，换的时候 `app.cpp` 不用动。

## 3. 颜色

作者面用 **OKLCH**（感知均匀，调明度不串色相），输出面固化为显示器的实际色域，
超出范围自动做 gamut mapping。这一层第一章已经建好并封装了，界面代码只写
OKLCH，不关心目标色域。

信息密度那一条（第 4 条）在实现上主要靠这层：分层排序用的是**明度差**而不是
色相差——明度差在任何色域、任何色觉类型下都成立。

## 4. 动画：三级低通，不是时间线

设计观第 3 条要求 $C^2$ 光滑，且「不允许孤立的因果」。这两件事一起排除了
时间线补间（timeline tween）。

### 为什么不用时间线

时间线的致命伤是**不可打断**。动画进行到一半时目标变了，要么突变，要么得写
一堆重映射逻辑。实测：一个补间动画在中途被打断，速度跳变 **100.7%**；同样
情况下三级低通的速度跳变 **0.4%**。

低通滤波天然可打断——它没有「动画」这个对象，只有「当前值追着目标值跑」。
目标随时可以改，输出永远连续。

### 三级级联的数学

一阶低通 `y' = (x - y)/τ` 串三级，阶跃响应

$$y(t) = 1 - e^{-s}\left(1 + s + \tfrac{s^2}{2}\right), \quad s = t/\tau$$

起点处 $y(0) = y'(0) = y''(0) = 0$——位置、速度、加速度**都从零起步**，这正是
$C^2$ 的来源。

| 到达 | 需要 |
|---|---|
| 50% | 2.67 τ |
| 90% | 5.32 τ |
| 95% | 6.30 τ |
| 99% | 8.41 τ |

速度峰值出现在 `s = 2.00 τ`（此时刚走完 32.3%），所以运动是「慢起—快—慢收」，
不是匀速。

按 95% 视为到位反推时间常数：

| 想要的观感 | τ |
|---|---|
| 120 ms（轻快，hover 反馈） | 19 ms |
| 200 ms（标准，按钮/输入框） | 32 ms |
| 300 ms（较重，面板展开） | 48 ms |
| 450 ms（沉，页面转场） | 72 ms |

### 实现上必须注意的一点

每帧的系数要写成

```cpp
float a = 1.0f - std::exp(-dt / tau);
value += (target - value) * a;
```

**不能**写成固定的 `value += (target - value) * 0.2f`。后者的实际时间常数随帧率
变化——60 Hz 和 144 Hz 上手感完全不同。用 `exp(-dt/τ)` 则与帧率无关：

| 刷新率 | τ=32 ms | τ=48 ms |
|---|---|---|
| 60 Hz | a = 0.406 | a = 0.293 |
| 120 Hz | a = 0.229 | a = 0.159 |
| 144 Hz | a = 0.195 | a = 0.135 |

### 什么用滤波，什么用状态机

滤波器负责**连续量**（位置、尺寸、颜色、透明度、圆角）。
状态机负责**离散事实**（当前是登录态还是注册态、请求有没有在飞）。

两者的接口是：状态机切换 → 改若干滤波器的目标值 → 滤波器把变化铺成连续动画。
不存在「播放一段动画」这种调用。

## 5. 布局、变换栈、命中测试

### 模式

即时模式（immediate mode）描述结构，但**动画状态是保留的**：每个元素有一个
稳定 id，id 对应一组滤波器状态。这样每帧重新描述 UI 树，动画却不会重置。

id 的稳定性是这套东西的地基。列表项用数据的主键，不用下标——用下标的话
插入一项会让后面所有项的动画状态错位。

### 变换栈与裁剪栈

设计观第 2 条要求「弹窗从按钮生长出来」，这需要：

- **变换栈** `push_transform(mat)` / `pop` —— 子元素跟着父元素一起动
- **裁剪栈** `push_clip(rect)` —— 生长过程中内容被裁在当前边界内

裁剪对 SDF 管线是廉价的：每实例带一个裁剪矩形索引，片元里对距离场取
`max(d, clip_d)` 就行，不需要 scissor 切 draw call。

### 命中测试

用**同一套 SDF** 做命中测试，不另写一套包围盒逻辑。好处是圆角、胶囊、圆形按钮
的可点区域和它看起来的形状严格一致——鼠标在圆角外面的那一小块不会误触。

命中测试要走变换栈的逆变换，所以变换必须可逆（只用平移/缩放/旋转，不用投影）。

## 6. 输入与 IME

中文输入是这个界面绕不开的部分（用户名可以是中文）。走 SDL3：

- `SDL_StartTextInput` / `SDL_StopTextInput` —— 只在文本框聚焦时开
- `SDL_EVENT_TEXT_INPUT` —— 已提交的文本
- `SDL_EVENT_TEXT_EDITING` —— **预编辑串**（拼音候选中的那段），必须单独渲染
  并加下划线，不能当成已输入内容
- `SDL_SetTextInputArea` —— 告诉系统候选窗该弹在哪。不设的话候选窗会飘到屏幕
  角落，中文输入直接不可用

文本框自身要处理：光标位置、选区、Home/End、Shift+方向键、双击选词、密码框的
掩码显示（掩码要按**字素簇**而不是字节数，否则一个汉字变三个点）。

### 指标

- 按键到字符出现在屏幕上：**下一帧**（≤16.7 ms）
- 预编辑串的变化同样是下一帧，且候选窗位置每帧跟随光标

## 7. 状态机

登录界面的离散状态：

```
        ┌──────────┐  切换  ┌──────────┐
        │  登录态   │ <───> │  注册态   │
        └────┬─────┘        └────┬─────┘
             │ 提交              │ 提交
             ▼                   ▼
        ┌─────────────────────────────┐
        │        请求飞行中            │
        └──────┬───────────────┬──────┘
               │ 成功           │ 失败
               ▼               ▼
          ┌────────┐      ┌─────────┐
          │ 已登录  │      │ 错误展示 │
          └────────┘      └─────────┘
```

设计观第 2 条的硬约束：**每一条转换都必须有对应的动画通道**。

- 登录 ↔ 注册不是换一屏，是邮箱那一栏从高度 0 长出来、其余项让出位置
- 提交不是弹一个 loading 遮罩，是提交按钮自己形变成进度指示
- 失败不是弹窗，是错误文字从对应输入框下方长出来，输入框边框同时变色 + 抖动
  （第 1 条要求「两种以上反馈」）

「弹窗凭空出现」在这个界面里应该一次都不出现。

## 8. 网络

真后端，可部署到生产环境。两侧都是 C++，**共享 wire 格式头文件**（同一个
`.h` 既被服务端也被客户端 include，字段对不上是编译错误而不是运行时 bug）。

- HTTP：**cpp-httplib** + **mbedTLS**（`CPPHTTPLIB_MBEDTLS_SUPPORT`），
  两者都已在 SDK 的 `libs` 组件里预编译好
- 局内实时传输（后面几章）：GameNetworkingSockets。**注意它现在还打不开**——
  依赖 Protobuf，SDK 里没有，`vkx add gamenetworking` 会当场说明

### 设计观第 1 条对网络层形状的硬性要求

> 确认接收要快（100 ms 内），交付结果可以慢，两件事必须解耦。

这不是 UI 层自己能解决的，它决定了网络调用的形状：**请求必须是异步的，且
UI 线程不允许等待**。

- 点击提交 → **同一帧**改状态机 → 按钮开始形变（承接反馈，远快于 100 ms）
- 请求在别的线程飞，回来时把结果塞进一个队列
- 主循环每帧取队列 → 改状态机 → 滤波器把结果铺成动画

绝对不能出现的写法：在事件处理里同步 `http.Get()`。那会卡住主循环，第 1 条和
第 3 条同时违反。

## 9. 头像上传：唯一需要第二条管线的东西

头像是位图，SDF 画不出来。这是整个界面里**唯一**打破「一条管线」性质的部分。

- 解码：**stb_image**（已在 SDK 的 `libs` 里，只有头文件）
- 上传：`VkImage` + `VkImageView` + `VkSampler`，走 staging buffer
- 绘制：新增一条采样纹理的管线，或给现有管线加一个「有没有贴图」的
  specialization constant 分支

**建议先做后者**：一条管线加一个特化常量，比两条管线少一半的状态切换，而且
圆角裁剪逻辑可以直接复用——头像是圆形的，正好是 `radius = 半边长` 的那个退化
情况，SDF 天然能裁。

传输：`multipart/form-data`，cpp-httplib 直接支持。

### 指标

- 头像解码到显示：解码在别的线程，主线程只做上传，不阻塞
- 上传中的进度必须可见（第 1 条），且是连续变化的（第 3 条）

## 10. 五条设计观 → 技术机制

| 设计观 | 机制 | 可测的指标 |
|---|---|---|
| **1 反馈** | 状态机与网络解耦；按下即改滤波器目标 | 承接反馈 ≤ 100 ms（实际是下一帧 ≤16.7 ms）；每个操作 ≥2 种反馈通道 |
| **2 因果** | 变换栈 + 裁剪栈；元素从源头生长 | 界面上零个「凭空出现」的元素 |
| **3 连续** | 三级低通级联 | $C^2$；打断时速度跳变 <1%（对照：时间线 100.7%） |
| **4 信息密度** | OKLCH 明度分层；大小/位置/动效排序 | first glance 能抓住主操作 |
| **5 新奇度** | hover 的抗拒/弹跳；非线性的状态指示 | —— 主观，但机制上要求滤波器目标可以被临时"推开" |

第 5 条最容易被做丢。它在实现上的抓手是：**滤波器的目标值允许被短暂扰动**
（hover 时目标往鼠标反方向推一点再放开），这在低通框架下是免费的——改目标值
就行，不需要任何额外机制。

## 11. 实施顺序

按依赖排，每一步都应该能单独跑起来看见东西：

1. **文字**——笔画字库解析 → `ui::segment()` → 能画一行字
2. **布局与命中测试**——变换栈、裁剪栈、id 稳定的滤波器状态池
3. **文本输入**——光标、选区、IME 预编辑串
4. **状态机与转场**——登录 ↔ 注册的生长动画
5. **网络**——异步请求、结果队列、错误展示
6. **头像**——纹理管线分支、上传、圆形裁剪
7. **打磨**——第 5 条，hover 抗拒、非线性指示

1–4 全程不需要新增任何 GPU 能力，5 不碰渲染，只有 6 要动 `gpu/` 层。

## 12. 未决

- **滤波器状态池的规模**——每个元素几个通道（位置 x/y、尺寸 w/h、颜色 4、
  圆角 1 = 9 个 float 起步），元素上千时是否需要按需分配。先按全量分配写，
  测出来再说。
- **小字号**——登录界面的辅助文字（「忘记密码？」）大概在 12–14 px，正好踩在
  笔画骨架的短板上。可能需要为小字号单独加一点 hinting，或者干脆把最小字号
  提到 15 px。**这一条要在第 1 步做完时就验证**，它可能推翻文字选型。
- **密码框掩码的字素簇处理**——UTF-8 到字素簇的切分需要一份表，笔画字库里
  有没有现成的信息可用，待查。
- **第 5 条的具体表现**——目前只有机制，没有具体设计。等 1–6 跑通后再定。
